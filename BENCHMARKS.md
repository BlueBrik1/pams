# Benchmarks: exact 3-share masked ML-KEM verification lane (1 coefficient / cycle)

**Common conditions (identical for all designs):**
- RTL generated by `models/gen.py` from the same HPC2 gadget, the same share-wise operations, the same pipeline aligner and the same accumulator.
- Supports d ∈ {4, 5, 10, 11} (ML-KEM-512/768/1024), selectable per coefficient.
- Nangate45 typical; Yosys 0.33 + ABC flow B (BUF_X1 drive, 5 fF load); HPC2 `keep_hierarchy`.
- OpenSTA data-path groups, I/O at the clock edge.
- P&R: OpenROAD (ORFS 26Q3) project flow, period target 2.0 ns, density 0.6, RCX extraction.
- **Measured values are tool estimates; there is no silicon.**

## 1. Synthesis (flow B; 5 mappings per design: ABC -D 500 with 0/3/6 pad modules, -D 400, -D 650)
| design | area µm² median [min, max] | worst-path delay ns median [min, max] | FFs (top) | HPC2 gadgets | random bits/cycle | decision latency |
|---|---|---|---|---|---|---|
| base (optimized Simple, W = 24, t = 13) | **21,598** [21,597, 21,598] | **1.649** [1.649, 1.650] | 1,565 | 57 | 171 | 31 + 4 cycles |
| PAMS-ripple (14-bit, ripple comparator) | 18,745 [18,741, 18,747] | 1.494 [1.493, 1.497] | 1,677 | 40 | 120 | 31 + 4 |
| **PAMS (14-bit, split comparator)** | **16,998** [16,998, 17,046] | **1.487** [1.487, 1.487] | 1,309 | 40 | 120 | 29 + 4 |

- **PAMS vs base:** **−21.3% area, −9.8% worst-path delay.** Every PAMS mapping is smaller and faster than every baseline mapping. The spread is < 0.3% for both designs.
- **Functional and security checks:**
  - every mapping passed the gate-level functional re-check (1,500 coefficients and about 270 ciphertext decisions per mapping, 0 mismatches);
  - every mapping passed the share-domain check (0 violations).
- **Note on the perturbations:** ABC -D 400 and 650 changed nothing relative to -D 500 for either design. The real variation comes from the pad perturbations.
- **Area split (base, mapping 0):** HPC2 gadgets 57 × 180.35 = 10,280 µm²; top-level logic (alignment registers, multipliers, public logic) 11,318 µm².
- **Area split (PAMS):** HPC2 gadgets 40 × 180.35 = 7,214 µm²; top-level logic 9,784 µm².
- **Critical paths (reg2reg):** base: the share-wise 24-bit exact scaling multiplier + mode shift + offset subtraction. PAMS-ripple: the public Low_c/Θ_c logic (before it was optimized).

## 3. Place and route (`runs/pnr_summary.json`)
**Batch 1, default project flow (`pnr/pnr.tcl`):**
- PAMS: routed at 45/50/55% utilization.
- **Baseline: all three runs FAILED** with `[ERROR RSZ-0060] Max buffer count reached` during hold repair. It had 566 hold-violating endpoints and 1,832 hold buffers inserted when it reached the default 20% cap.

**Batch 2, identical for both designs:** a copy of the flow (`tools/pnr_mv.tcl`) whose only change is `repair_timing -hold -max_buffer_percent 60`.

| run | achieved period ns | hold WNS ns | cell area µm² | die µm² | DRC | wire µm | buffers | power W (vectorless) |
|---|---|---|---|---|---|---|---|---|
| base u45 | 1.795 | +0.001 | 23,819 | 49,693 | 0 | 81,450 | 2,087 | 0.0513 |
| base u50 | 1.801 | +0.008 | 23,770 | 44,811 | 0 | 81,116 | 2,028 | 0.0514 |
| base u55 | 1.810 | +0.004 | 23,762 | 40,812 | 0 | 80,728 | 2,035 | 0.0513 |
| PAMS u45 | 1.614 | +0.006 | 18,729 | 39,386 | 0 | 59,780 | 1,561 | 0.0402 |
| PAMS u50 | 1.613 | +0.001 | 18,704 | 35,525 | 0 | 59,067 | 1,541 | 0.0401 |
| PAMS u55 | 1.607 | +0.002 | 18,652 | 32,362 | 0 | 58,601 | 1,511 | 0.0398 |

- **Medians:** base 1.801 ns / 23,770 µm² cell / 44,811 µm² die; PAMS 1.613 ns / 18,704 / 35,525.
- **PAMS: −10.4% period, −21.3% routed cell area, −20.7% die, −27% wirelength.**
- All 6 runs have setup met at the 2.0 ns target, positive hold slack, 0 DRC and RCX parasitics.
- PAMS results are identical in batches 1 and 2, because PAMS never reached the cap.

**Power:** vectorless, at a 2.0 ns clock, default activity. It is an indication only, **not an energy measurement**.

## 4. What is not measured
- **Scope:** complete-decapsulation effect. This is a subsystem result.
- **Comparisons not made:** published-circuit baselines (no matched second-order ASIC verifier exists); X2X-style conversion gadgets (would apply to both lanes); other gadget families (DOM, HPC3).
- **Physical evidence:** no side-channel measurements.
