# Phase XIII benchmarks: PAMS against the strongest reproducible exact second-order competitors

## Conditions
All conditions are identical for every row and match Phase XI (DESIGN_CONTRACT.md):
- **Library and synthesis:** Nangate45 typical; Yosys 0.33 + ABC flow B (BUF_X1 drive, 5 fF load); HPC2 `keep_hierarchy`.
- **Mappings:** five per design (ABC -D 500 with 0/3/6 pad modules, -D 400, -D 650).
- **Timing:** OpenSTA data-path groups, I/O at the clock edge.
- **P&R:** OpenROAD (ORFS 26Q3), the Phase XI batch-2 flow (`tools/run_pnr_mv.sh`, unchanged), 2.0 ns target, utilizations 45/50/55 %, RCX extraction. The frozen `base` / `pams` routed rows are the Phase XI runs (`runs/pnr2_*`) of the same flow.
- **Re-synthesis check:** both frozen designs were re-synthesized from their byte-identical RTL in this phase and reproduce the Phase XI synthesis numbers exactly.
- **Interface:** one coefficient per cycle (II = 1) for every design; latency = per-coefficient decision stage + 4 cycles to the ciphertext decision.
- **Depth:** the number of share-wise front-end pipeline stages added relative to the frozen designs:
  - p / pr: +1;
  - q / qr: +2.
- **Variant suffixes** (CANDIDATES.md):
  - j: just-in-time CSA operands;
  - p / q: extra front-end stages;
  - r: public window logic retimed into those stages (PAMS only; it needs p or q);
  - bk: Brent–Kung carry.

Tables generated by `models/tables.py` from `runs/cbench.json` and the P&R `metrics.txt` files (`runs/tables.md`).

## 4. Approaches rejected by measured lower bound or by contract
- **Coron et al. 2023 arithmetic zero test / candidate products (exact per-coefficient variant):**
  - The block used for the bound is `rtl/mul12.v`, one registered **unmasked** 12 × 12-bit integer multiplier with no reduction. It synthesizes to 1,241 µm² (48 FFs, 1.165 ns) under the same flow (`runs/syn_mul12/result.json`).
  - An exact path for d = 10/11 needs ≥ 3 masked mod-q multiplications per coefficient, each with ≥ 9 partial products at 3 shares.
  - That gives ≥ 27 × 1,241 = 33,500 µm², about 2.0 × the whole frozen PAMS lane. The bound ignores modular reduction, refresh randomness, the zero test and the separate d = 4/5 path.
  - **Rejected** without RTL.
- **Probabilistic comparisons** (D'Anvers 2022 / 2023 hybrid and GF, CGMZ23 random linear combinations): excluded by the exact-comparison contract.
- **X2X DOM / t-NI gadget substitution and half-cycle paths:** outside the contract's security model (FAIRNESS_AUDIT.md §3). They would apply to PAMS equally.

## 5. Mapping and P&R variation
- **Synthesis area:** the spread over the 5 mappings is ≤ 0.6 % for every design.
  - All area differences between PAMS and any competitor (≥ 14 %) are 20× or more beyond it.
  - No PAMS mapping is larger than any competitor mapping at the same or any depth: largest PAMS mapping 18,179 µm² (pams_q) versus smallest competitor mapping 19,915 µm² (base_j).
- **Synthesis delay:** the spread is ≤ 0.2 % for the frozen designs and for base_j / base_p / base_jp / base_q / base_jq, and 1–2 % for hoc_jp, hoc_jq and base_bkp. It is larger for several PAMS j / p variants:
  - pams_j: 1.493–1.565;
  - pams_p: 1.206–1.306;
  - pams_jp: 1.234–1.330.

  The structure-dependent mapping noise of ABC is up to 8 %.
- **Routed delay:** base_jq varies 1.150–1.241 ns across utilizations; pams_jqr varies 1.153–1.162 ns.
  - At depth +2, the 4.9 % median routed-period difference is **not** larger than the P&R variation: base_jq u45 (1.150) is faster than pams_jqr u50 (1.162).
  - At depth 0 and +1, the routed ranges do not overlap. PAMS is faster by ≥ 10 % (frozen versus frozen; worst-case pair 1.614 versus 1.795) and by ≥ 17 % (pams_jpr versus the depth-+1 base family; worst-case pair 1.261 versus 1.527).

## 6. Critical paths (mapping 0, worst reg2reg path; start register → end register)
| design | start → end | stage limiting the clock |
|---|---|---|
| base, base_j | x1r → y1 (via s1) | share-wise constant multiplier + mode shift (frozen front end) |
| hoc | x0r → y0 | the same, 25-bit |
| base_p, base_jp, hoc_jp | x_r → fq (m = x · M) | the share-wise constant multiplier alone |
| base_q | x2r → ml2 | first half of the split multiplier (partial product) |
| base_jq, hoc_jq | ml1 / mh1 → fq1 | second half of the split multiplier (partial-product sum) |
| pams | x0r → y0 | share-wise constant multiplier + Low_c subtraction |
| pams_jp, pams_jpr | x2r → s2p | the share-wise constant multiplier alone |
| pams_j, pams_p, pams_q, pams_jq | c0 / e0 → lowr / thr | the **public** window logic (c, d → Low_c, Θ_c), a stage of public logic the baseline does not have |
| pams_jqr | c0r → lowrq | second half of the retimed public window logic (Low_c = (2c − 1) 2^e + qq) |

**Consequences:**
- Every design is still front-end limited: the share-wise multiplier, or, for PAMS, its public constant logic. None is limited by the masked kernel.
- With further pipelining of these share-local or public stages, both families approach a common floor set by the gadget network (HPC2 output XOR + CSA XOR into a register).
- PAMS's delay advantage therefore **depends on the pipeline budget**: 9.7–20.9 % at depth 0 and +1 (synthesis and routed), 2.3 % (synthesis) and 4.9 % (routed median) at +2 (within P&R variation), and expected to vanish with deeper pipelining.
- The **area** advantage does not depend on depth: it comes from 40 versus 57 gadgets and a 14- versus 24-bit lane, and it persists at every depth measured.
